# antipython

An openCode plugin that blocks file edits performed through a Python interpreter.

Registered in `~/.config/opencode/opencode.jsonc`:

```jsonc
"plugin": [ ..., "/home/desu/opencode-antipython" ]
```

## What it blocks

The `tool.execute.before` hook inspects the `command` argument of `bash`,
`term_host_exec` and `term_pty_exec`, and throws when a Python interpreter is
used as the thing that mutates a file.

| blocked | allowed |
| --- | --- |
| `python3 -c "open('a','w').write(x)"` | `python3 -c "print(1)"` |
| `python3 - <<'PY' ... os.remove(...) ... PY` | `python3 -m pytest -q` |
| `python3 <<< "open('a','w')"` | `python3 script.py --flag` |
| `printf "open('a','w')" \| python3` | `uv run pytest` |
| `cat > fix.py <<'PY' ... shutil.rmtree(...) ... PY` then `python3 fix.py` | `python3 -c "print(len(open('f').read()))"` |
| `python3 -c "import subprocess; subprocess.run(['sed','-i',...])"` | `python3 -c "import sys; sys.stdout.write('x')"` |

Detection is inline-code only: `python3 script.py` and `python3 -m <module>`
are always allowed, since a script authored in the repo is a real script. A
script *generated by the same shell command* is treated as inline code, because
that is just an interpreter with extra steps.

Write-intent signals in inline code: `open()` in a writing mode, `os.open` with
`O_WRONLY`/`O_CREAT`/..., `.write()`, `.write_text()`/`.write_bytes()`,
`print(..., file=...)` (but not `file=sys.stdout`), `sys.stdout = ...`,
`json.dump`/`pickle.dump`/`csv.writer`, `os.remove`/`os.rename`/... , any
`shutil.*`, pathlib mutations, and `subprocess`/`os.system`/`os.popen` whose
arguments contain a mutating command (`rm`, `mv`, `sed -i`, `>` ...).

## Development

```sh
bun test          # 59 detector tests
bun run build     # tsc -> dist/
```

`src/detect.ts` is the detector (shell-aware splitter, interpreter finder,
payload classifier, edit-intent scanner). `src/index.ts` is the thin plugin
wrapper.
